# 幼儿园上学打卡统计 —— 设计文档

日期：2026-09-16
状态：待评审

## 1. 背景与目标

孩子今年上小班，每天只上半天学，家长原本在家里的纸质日历上做标记，但纸质日历只能"记"，不能"算"——这个学期一共请了多少天假，只能自己一天天去数。

本项目的目标是做一个只服务于自己家的小应用：

**打开就能打卡，打卡完自动出统计，一眼看得出这个学期上了多少天、请了多少天假。**

具体目标：

- 记录每天出勤或请假，两次点击内完成
- 支持补录（昨天忘了记）和提前请假（明天开始请三天）
- 自动跳过周末和节假日，不用人工维护
- 按月和按学期给出出勤、请假、未记录三类天数，并列出请假明细
- 手机和电脑都能打开，两位家长共用同一份数据

## 2. 非目标

以下内容明确不做，避免第一版被拖慢：

- 不做退费金额计算（家长明确表示不涉及退费）
- 不做多孩子、多家庭
- 不做老师端或幼儿园端
- 不做消息推送提醒
- 不做离线打卡（先保证联网可用即可，后续有需要再加）

## 3. 使用场景

1. 早上送完孩子，在幼儿园门口打开链接，点「今天去了」。
2. 孩子咳嗽请假，点「今天请假」，选"病假"，填备注"咳嗽"，如果预计请三天就选三天，后面两天自动标成请假。
3. 周末想起来周二忘了记，打开日历点那天补上。
4. 月底或学期末，打开统计页看到"本月出勤 18 天、请假 3 天；本学期出勤 42 天、请假 5 天"，以及一条条请假明细。

## 4. 技术架构

### 4.1 整体形态

```
手机/电脑浏览器
      │  HTTPS  https://<子域名>
      ▼
Nginx Proxy Manager（已存在，负责 TLS 和反向代理）
      │  http://attendance:3000（Docker 内网）
      ▼
attendance 应用容器（Node.js：既发前端静态文件，也提供 REST API）
      │  mysql://<已有 MySQL 容器>
      ▼
MySQL（复用现有容器，只新建一个库）
```

要点：

- **只有一个自建容器**。前端静态资源和 API 由同一个 Node 进程提供，减少部署面。
- **不新建 MySQL 容器**，复用服务器上已有的那个，只新建 `attendance` 库（另建 `attendance_dev` 供本地开发）。
- **TLS 和域名由 Nginx Proxy Manager 负责**，应用只监听 HTTP 3000 端口，不管证书。
- 应用容器加入 MySQL 所在的 Docker 网络，用容器名互访，不往宿主机暴露额外端口。

### 4.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vite + React + TypeScript | 四个视图，组件化后改动成本低；构建产物是纯静态文件 |
| 后端 | Node.js + Fastify + mysql2 | 接口就十来个，不需要 ORM 的重量 |
| 数据库 | MySQL 8（复用现有容器） | 服务器上已经有了 |
| 部署 | Docker + docker compose | 服务器上已有的方式 |
| 反向代理 | Nginx Proxy Manager | 服务器上已有，自动申请 Let's Encrypt 证书 |
| 测试 | Vitest | 统计逻辑是纯函数，最容易也最值得测 |

### 4.3 仓库结构

```
server/            API 与静态文件服务
  src/
    db.ts          连接池
    schema.sql     建表语句（幂等）
    auth.ts        口令校验、Cookie 签发与验证
    stats.ts       统计口径（纯函数，重点测试对象）
    routes/
      records.ts   打卡记录读写
      settings.ts  学期与节假日配置
      stats.ts     统计与导出
web/               前端
  src/
    views/         主屏 / 日历 / 统计 / 设置
docs/superpowers/specs/  设计文档
Dockerfile         多阶段构建：构建前端 → 打包含后端的运行镜像
docker-compose.yml
.env.example
```

## 5. 数据模型

### 5.1 打卡记录 records

| 字段 | 类型 | 说明 |
|---|---|---|
| date | DATE 主键 | 一天最多一条 |
| status | ENUM('present','leave') | 出勤 / 请假 |
| reason | VARCHAR(16) NULL | 病假 / 事假 / 园里停课 / 其他，仅请假时有值 |
| note | VARCHAR(200) NULL | 自由备注，例如"咳嗽发烧" |
| by_name | VARCHAR(32) NULL | 谁记的：妈妈 / 爸爸 |
| updated_at | TIMESTAMP | 最后修改时间，自动更新 |

**关键设计：不存"未记录"状态。** 「未记录」= 某天在 records 里查不到。这样不会出现记录存在于数据库、状态却是"未记录"的矛盾状态，日历上删掉一天就是 DELETE 一行。

**关键设计：不存"请假区间"。** 一次请三天，就是把三天各写一行；日历上相邻的请假日期在渲染时自动连成一片。批量录入是接口能力，不是数据结构。

### 5.2 节假日 holidays

| 字段 | 类型 | 说明 |
|---|---|---|
| date | DATE 主键 | 放假的日子 |
| label | VARCHAR(64) | 例如"国庆节""园里运动会" |

幼儿园的放假安排不一定和法定节假日完全一致（可能提前放一天，也可能有自己的活动日），所以这张表必须可手动增删，不能写死在代码里。周末由程序按星期几推导，不放进这张表。

### 5.3 学期 terms

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INT 主键 | |
| name | VARCHAR(64) | 例如"2026 秋季学期" |
| start_date | DATE | 开学日 |
| end_date | DATE | 学期最后一天 |
| is_active | BOOL | 当前学期，统计和主屏默认用它 |

默认值按家长提供的信息预填：开学日 2026-09-07（周一，与"今天是第二周周三"吻合），结束日待家长确认。学期起止和节假日都由家长在设置页自行修改。

### 5.4 应用配置 app_settings

简单的 key/value 表，存放不宜写死在代码里的配置（例如家庭口令的哈希、展示偏好等）。

### 5.5 时区处理

所有日期都当作**本地日历日期**处理，一律用 `YYYY-MM-DD` 字符串在前后端之间传递，数据库用 `DATE` 类型，不用 `DATETIME`，也不做 UTC 换算。服务器时区固定为 `Asia/Shanghai`。这是"记录日期"类应用最容易踩的坑，需要在代码里明确约束。

## 6. 权限与会话

两位家长共用一份数据，但需要知道"这条是谁记的"（by_name 字段）。

- 服务端配置两个口令：`CODE_MOM`、`CODE_DAD`，分别对应妈妈和爸爸，放在环境变量里。
- 登录页输入口令，验证通过后签发一个 httpOnly + Secure + SameSite=Lax 的 Cookie，内容为 `{who, exp}` 加 HMAC 签名，有效期 90 天。手机上只需登录一次。
- 所有 API 除 `/api/login` 和 `/api/health` 外都要求有效 Cookie。
- 登录接口限制尝试频率（每分钟 5 次），避免口令被暴力破解。
- 口令首次部署时从环境变量读取，之后可在设置页修改并写回数据库；数据库里存了就以数据库为准，不必改环境变量重启容器。

## 7. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/login | 提交口令，签发 Cookie |
| POST | /api/logout | 清除 Cookie |
| GET | /api/health | 健康检查，供 Docker 和反代使用 |
| GET | /api/records?from=&to= | 按区间取记录，日历和统计共用 |
| PUT | /api/records/:date | 新增或覆盖某天 |
| POST | /api/records/bulk | 一次写入多天（连续请假） |
| DELETE | /api/records/:date | 删除某天记录 |
| GET | /api/terms | 学期列表 |
| PUT | /api/terms/:id | 修改学期起止 |
| GET | /api/holidays | 节假日列表 |
| POST | /api/holidays | 新增节假日 |
| DELETE | /api/holidays/:date | 删除节假日 |
| GET | /api/stats?scope=month\|term&month=YYYY-MM | 出勤/请假/未记录天数 + 请假明细 |
| GET | /api/export?format=json\|csv | 导出全部记录和配置 |

接口约定：请求与响应均为 JSON；出错时返回 `{error: {code, message}}`，HTTP 状态码语义正确；写操作返回写入后的记录。

## 8. 界面设计

四个视图，底部标签栏切换。

### 8.1 主屏（打开就是这里）

- 顶部：今天的日期和星期
- 中间：两个大按钮 —— 「今天去了」「今天请假」，按钮高度足够，单手可点
- 点「今天请假」弹出面板：原因标签（病假 / 事假 / 园里停课 / 其他）、备注输入框、"请几天"步进器（默认 1 天，可到 7 天）
- 已打卡状态下，按钮变成当前状态展示，旁边有"改一下"入口
- 顶部条件提示条：如果有过去的上学日未记录，显示"9/12、9/15 还没记录，点这里补"；如果有未来日期的记录（提前请假），显示"已请 9/17 起 3 天"

### 8.2 日历

- 月视图，可左右切月
- 颜色：绿色 = 出勤，黄色 = 请假，灰色 = 周末/节假日，浅黄 = 未来已请假的日期，空白 = 未记录（今天之后的日期也留白，但不算未记录）
- 点任意日期弹出编辑面板（改状态、改原因备注、删除记录）
- 顶部显示本月小计："出勤 18 · 请假 3 · 未记录 1"

### 8.3 统计

- 本月亮点数字：出勤 X 天、请假 Y 天、未记录 Z 天
- 学期累计：同样三个数字，另加"应上学天数"
- 请假明细列表：日期、星期、原因、备注，按时间倒序
- 导出按钮：JSON / CSV（CSV 用 Excel 能直接打开的编码）

### 8.4 设置

- 学期管理：新增/编辑学期起止，切换当前学期
- 节假日管理：按日期增删，可填说明
- 家庭口令修改
- 显示当前登录身份（妈妈 / 爸爸）

### 8.5 移动端形态

- 页面加 `manifest.json` 和 `apple-touch-icon`，可以"添加到主屏幕"，打开是全屏无地址栏，观感接近原生 App
- 配色用低饱和的暖色系（米白底，加上一组柔和的绿/黄/灰状态色），按钮尺寸按手机拇指操作设计
- 第一版不写 Service Worker，不做离线缓存

## 9. 统计口径

这是整个应用唯一需要严谨定义的部分，也是最容易算错的部分。

**应上学日** = 学期起止区间内，周一至周五，且不在 holidays 表里的日期。

统计范围有两个：本月（自然月与学期区间的交集）和本学期（整个学期区间）。两个范围的内部口径完全一致：

| 类别 | 定义 |
|---|---|
| 出勤 | 应上学日，且 records 中 status = present |
| 请假 | 应上学日，且 records 中 status = leave |
| 未记录 | 应上学日，日期在今天之前，且 records 中查无此日 |
| 待打卡 | 就是今天，且还没有记录（不计入未记录） |

补充规则：

- 周末和节假日即使被标记了请假（例如周末生病顺手标了一下），也**不计入**请假天数，只作为备注性质的记录存在
- 未来日期不计入任何"未记录"，只影响"已提前请假"的提示
- 本月统计是自然月与学期区间的交集，学期外的日期不参与计算
- 请假明细只列应上学日内的请假

以上口径全部实现在 `server/src/stats.ts` 的纯函数里，输入是"记录数组 + 节假日集合 + 学期区间 + 今天"，输出是三个天数加明细，不依赖数据库和当前时间，便于测试。

## 10. 部署方案

### 10.1 镜像

多阶段 Dockerfile：

1. 阶段一：Node 镜像里 `npm ci` + 构建前端，产出静态文件
2. 阶段二：安装后端依赖，复制后端代码和前端构建产物，以非 root 用户运行
3. 启动时执行幂等的 `schema.sql`（`CREATE TABLE IF NOT EXISTS`），保证首次部署自动建表

### 10.2 docker compose

只定义一个 `attendance` 服务：

- 加入 MySQL 所在的 Docker 外部网络
- 端口只在 Docker 内网暴露 3000，不映射到宿主机
- 环境变量从 `.env` 读取：数据库连接、`CODE_MOM`、`CODE_DAD`、`APP_SECRET`、`TZ=Asia/Shanghai`
- 配置 healthcheck 指向 `/api/health`
- 容器名 `attendance`，方便反代直接按名字寻址

### 10.3 Nginx Proxy Manager

在已有的 NPM 里新增一个 Proxy Host：

- Domain：家长指定的子域名，例如 `attendance.example.com`
- Forward Hostname：`attendance`（同网络时用容器名）或宿主机 IP + 映射端口
- Forward Port：3000
- 开启 SSL，申请 Let's Encrypt 证书，强制 HTTPS

### 10.4 首次部署需要准备

- 服务器上新建数据库 `attendance`（字符集 utf8mb4），并为应用创建专用账号，只授权该库
- MySQL 容器所在的 Docker 网络名称
- 一个指向服务器的子域名

## 11. 测试策略

| 层次 | 内容 |
|---|---|
| 单元测试（Vitest） | 统计口径：含节假日、跨月、学期边界、周末标记请假、今天未记录等场景，逐个断言天数 |
| 接口测试 | 登录、打卡 upsert、批量写入、删除、统计接口的返回结构 |
| 手工验收 | 真手机打开链接打卡一次，电脑端确认看到同一条记录；再删掉，两端同步消失 |

统计口径的单元测试是重点，因为它是唯一"算错了也不会报错"的地方。
